# UX audit — Document workspace, Administration, Standards, Ask

**Status: 📁 `ANALYSIS` — a record of what was found and fixed. Decides nothing, locks nothing.**
**Date:** 2026-09-14 (night). **Scope set by the owner:** Document workspace · Standards / Admin ·
Ask / Research. Client Profiles excluded — another session owns `feat/client-profiles`.

---

## How this was done, and why it matters

Every defect below was found by **rendering the real application** with real seeded data at
1366×768 and 1920×1080 and looking at it — not by reading source. That distinction produced the
whole list: **three of the five root causes are rules that were never written at all**, which no
amount of code review finds, because there is nothing on the page to review.

| Root cause | How it was invisible in source |
|---|---|
| `.ws-filter-bar` had **no CSS rule anywhere** | The class is in the markup and looks intentional |
| `.ws-adminnav .ws-tab` carried only `text-decoration: none` | `.ws-tabs`'s child rules select `[role="tab"]` / `[aria-pressed]`; these are `<Link>`s with `aria-current`, so nothing matched |
| Legal configuration had **no container element** | It returns a bare `<>` fragment; nothing looks wrong until it is 1920px wide |
| `.ws-dock__note { margin: 0 }` | A later rule silently overrode the centring set 17 lines above it |
| `.ws-admin` had no measure | Fine at 1366, edge-to-edge at 1920 |

---

## What was wrong, and what it is now

### 1. Administration ran edge to edge, and the roster began below the fold

At 1920 the heading started at x=0 while every other screen sits in a centred column. Worse,
`.ws-filter-bar` was unstyled, so its five `.ws-field` children stacked at full width — **≈370px of
filter controls before a single row of data**.

**Now:** a 90rem column (wider than the 72rem prose measure, because a seven-column roster is sized
by its columns, not by a reading measure), and the five filters on one row at both 1366 and 1920.
The table starts at y≈330 instead of y≈580.

A first attempt used 72rem and was reverted after looking at it: the timestamp cells broke
mid-token (`2026-09-` / `14`). Recorded because the narrower measure is the tempting choice.

### 2. The Administration section links read as one sentence

`Users Departments Roles & permissions Audit log` — four `<Link>`s with a 4px flex gap and no
padding, border or active treatment, because they match none of `.ws-tabs`'s child selectors.

**Now:** real tabs, with the current section filled dark and carrying `aria-current="page"`.

### 3. Legal configuration had no container — and two actions printed as one word

At 1920 the explanatory paragraphs ran the full 1900px, far past any readable measure. Separately,
two `button.link` actions rendered as **`Show stored valuesDraft a new version`** — adjacent JSX
siblings whose newline whitespace is stripped at compile time.

**Now:** the same 72rem column as the rest of the app, prose capped at 80ch, and the two actions
separated as the two actions they are.

### 4. The publish field's label carried its own instructions

`Requirement codes to activate (comma separated; blank to publish current active configuration
only)` was one bold label wrapping to two lines. `.field__hint` already existed in `globals.css`
with **no way to render it** — the `Field` primitive had no slot for it.

**Now:** `Field` takes an optional `hint`, rendered as `.field__hint` and wired to the input through
`aria-describedby`, so it reaches a screen reader as help rather than as part of the field's name.
The label is `Requirement codes to activate`; the instruction is help text beneath it.

This is the field the owner uses to publish the 33 standards, which is why it was worth fixing
tonight rather than noting.

### 5. Ask, with the document hidden, was a form at the bottom of an empty page

The conversation was capped at 72ch but **the input row was not** — a 1900px field sat under a
650px column with its send button a full screen away from the words being typed. The honesty note
under it stayed pinned to the far left. The empty state floated at the *top* of a ~700px void.

**Now:** the input tracks the same measure as the conversation, the note is centred beneath it, and
the log is **bottom-anchored** (`margin-top: auto` on its first child, which resolves to 0 once
content overflows, so scrolling is untouched). It now reads the way the owner asked for on
2026-09-10 — "a proper conversational AI workspace… similar in usability to ChatGPT".

## What was deliberately NOT done

* **No shadcn component was added.** The owner's standing terms are incremental adoption where a
  primitive *solves a problem*; none of tonight's five defects was a missing primitive. Two genuine
  candidates from the 2026-09-10 audit remain open and unstarted: the hand-rolled row-action menu
  (→ `DropdownMenu`) and the absent Tooltip primitive.
* **`StatePill` / `AXIS_CLASS`, `AccessRestricted`, `DecisionControl`, `EscalateControl` and table
  density** — untouched, per CLAUDE.md.
* **Client Profiles** — untouched; another session owns that branch.
* **The vertical emptiness below short content** on the workspace and Standards screens is left
  alone. It is a consequence of genuinely short content, not a layout fault, and filling it would
  mean inventing UI.
