# Docling — the PDF TABLE reader (owner decision 2026-10-15, "use docling"), in its OWN
# venv. Tables only: prose is always the standard parser's, and only pages with >= 3 thin
# horizontal rules of one horizontal extent are sent (18 of the 137 approved-corpus pages),
# in runs of at most 12 pages; a document with more than 60 such pages is not sent.
# Never installed into the API's environment: the API runs it as a child process
# (backend/legalmind/ingestion/docling_runner.py) and falls back to its own parser.
#   python3 -m venv /opt/legalmind/docling-venv
#   /opt/legalmind/docling-venv/bin/pip install -r ops/docling/requirements.txt
#   /opt/legalmind/docling-venv/bin/docling-tools models download \
#       -o /opt/legalmind/docling-models layout tableformer     # the only download
#   LEGALMIND_DOCLING_PYTHON=/opt/legalmind/docling-venv/bin/python   (API env file)
#   LEGALMIND_DOCLING_MODELS=/opt/legalmind/docling-models
# It runs offline from those models (AM-30) and needs tesseract (eng) on the host.
# Measured 2026-10-15 (/usr/bin/time): 13-16 s and 1.26-1.47 GB peak RSS for 1-3 pages
# sent (the SLAs); ONE 12-page run (the most a run is sent) 40-71 s and 1.86-1.91 GB
# (Companies Act 2013, its first and last 12 gated pages).
# MemoryMax: the child runs in the API's cgroup, which already peaks ~1.4 GB under
# MemoryMax=3G — raise it to 5G before setting the two variables. The child is started
# under util-linux `choom -n 1000`, so if the cgroup still runs out the kernel kills it,
# not the API.
