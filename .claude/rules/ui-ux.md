# UI and UX work

A task is UI/UX work if it touches `frontend/`, a screen, a component, styling, layout,
typography, colour, iconography, spacing, motion, accessibility or a chart — **including a
one-line CSS change** (owner, 2026-08-26).

## The bar (owner, 2026-10-28 / 11-02)

Enterprise-grade, never "vibe-coded": every component has all its states (empty, loading,
error, full, no-access), one icon set (Lucide), tokens only, keyboard + WCAG 2.2 AA, desktop
**and phone**. Follow the best guidance from any source (Linear, Carbon, Atlassian, Fluent,
Juro/Ironclad/SpotDraft for CLM). DD-4-level finish from the first pass; "no marketing copy" is
not licence for bare design.

**Superseded — do not apply:** the 2026-08-31 "UI frozen" rule and the 2026-08-26 "backend
first, UI later" rule (both replaced by the bar above).

## The method — one page at a time (owner, 2026-11-03)

1. Load the skills **before** writing markup: `frontend-design:frontend-design` and
   `ui-ux-pro-max` (with its `ui-styling`, `design-system`, `design`); `dataviz` for any chart,
   meter, KPI tile or sparkline; `figma:*` skills where Figma fits (each loaded before its MCP
   tool; Figma needs auth on first use). `brand`, `banner-design`, `slides` are marketing tools —
   not for product screens.
2. Read the design knowledge base: [DESIGN.md](../../DESIGN.md), `docs/design/*`
   (DESIGN_SYSTEM, DESIGN_DECISIONS DD-*, UI_PATTERNS, UX_AUDIT*, WORKSPACE_UI_PLAN,
   SHADCN_ADOPTION_REPORT) and the page's existing components/tokens.
3. Write a short page plan (layout sketch, type, tokens, the one memorable element); cut generic
   defaults (card kits, ALL-CAPS eyebrows, middle-dot meta strings, "→" on buttons, mono labels).
4. Build **that page only**. Screenshot every state (each persona, empty/full, 1440 and 390,
   keyboard) and critique.
5. A **separate critic agent** (fresh context: screenshots + plan + KB, not the builder's
   conclusions) challenges it against real products, enterprise design systems, WCAG 2.2 AA and
   plain language; the builder fixes what holds up; then the next page.

## What binds, in order

1. **CLAUDE.md rules 1–23** — rule 18 above all: the UI implements no legal evaluation logic,
   never talks to the database, and permission gating is presentation only.
2. **Three product prohibitions:** never imply a probability, confidence score or "the AI thinks"
   hedging (rule 12); no urgency theater; an omitted confidential field stays omitted — never
   nulled or greyed (`SEC-07`, `LEGAL-02`).
3. **Never touch** (contracts, not styling): `StatePill` / `AXIS_CLASS` in
   `components/Primitives.tsx` (the five state axes, RESOLVED ≠ MATCH), `AccessRestricted.tsx`
   and any omission-as-absence logic, `DecisionControl.tsx` / `EscalateControl.tsx`
   (no optimistic UI, bespoke 409 handling), and dense tables. Locked behaviour such as `AM-133`
   and "no token streaming" in Ask still binds.
4. **DESIGN.md and DD-1…DD-n are reference, not binding constraints for new UI** (owner,
   2026-10-13: "do not think design.md is a final"). Read them; where they are already correct,
   the existing visual language wins; do not raise a DESIGN.md conflict as an owner question.
   Presentation work locks nothing and amends no entry in LOCKED_DECISIONS.md.

## shadcn/ui + Tailwind (approved 2026-09-10, incremental only)

- No big-bang migration; add a primitive only where it improves consistency, accessibility or
  maintainability over the hand-rolled one.
- Restyle every adopted primitive to the existing tokens (`--surface`, `--line`, `--accent`,
  `--attention`, `--error`, `--space-*`, `--text-*`); never let shadcn/Radix defaults set the look.
  A Radix "disabled + tooltip" is the wrong shape for confidential omission.
- Before installing: `git status` and `git worktree list`; verify `prebuild`/deploy scripts still
  work unmodified. Ambiguous product/visual cases are `OWNER DECISION REQUIRED`.

## Frontend gotchas

- `frontend/AGENTS.md` is regenerated by `next dev` ("This is NOT the Next.js you know" — read
  `node_modules/next/dist/docs/` before writing Next.js code). Do not hand-edit it.
- **Never `npm run build`/`next build` in the deploy tree** (it took the live site down,
  2026-09-01). Local builds use `LEGALMIND_NEXT_DIST=.next-<name>` and
  `LEGALMIND_API_ORIGIN=http://127.0.0.1:<your API port>` — without the origin, a build proxies
  to production `:8000`. A build edits `tsconfig.json`/`next-env.d.ts`; revert them.
- **Visual baselines are CI-cut only**: never `--update-snapshots` locally; inspect CI's diff, then
  adopt CI's baselines. A green job 15 can hide sub-tolerance drift below 1152px.
- Real-browser checks: skill `local-stack`.
